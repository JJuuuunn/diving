# API, Validation, and Async State

## 언제 읽는가

Google Apps Script, HTTP 요청, 외부 응답, 캐시 갱신 또는 비동기 목록을 변경할 때
읽는다.

## 필수 규칙

- 모든 HTTP 요청은 `src/api/`에서 수행한다.
- `response.ok`와 애플리케이션 응답 상태를 모두 확인한다.
- `response.json()` 결과는 `unknown`으로 간주하고 런타임 검증 후 반환한다.
- API 함수는 화면에 바로 표시할 문자열보다 원인 구분이 가능한 오류를 발생시킨다.
- 사용자 오류 메시지에는 비밀값, 내부 경로, 원본 응답 전체를 포함하지 않는다.
- 제출 요청은 loading 상태로 중복 실행을 차단한다.
- 실패 후 다시 시도할 수 있어야 하며 실패를 성공/완료 상태로 고정하지 않는다.
- 비동기 상태는 최소 `loading`, `error`, 기존 데이터 유무를 구분한다.
- loading 종료는 `finally`에서 보장한다.
- 새로고침 중 검증된 기존 데이터가 있으면 유지하고 비차단 진행 상태를 표시한다.
- 원격 실패 시 검증된 캐시 또는 정적 스냅샷만 fallback으로 사용한다.
- 오래된 요청이 최신 요청 결과를 덮지 않도록 중복 요청이나 요청 순서를 관리한다.
- 컴포넌트 해제 후 상태 변경 가능성이 있으면 요청 취소 또는 유효성 검사를 둔다.

## 날짜와 URL

- 달력 날짜는 `YYYY-MM-DD`, 시점은 ISO timestamp로 구분한다.
- 한국 운영 날짜의 비교와 표시는 `Asia/Seoul` 기준을 명시한다.
- 외부 URL은 허용 프로토콜과 필요한 도메인 규칙을 검증한다.

## 허용 예외

- 빌드/수집용 Node 스크립트와 Google Apps Script의 네트워크 호출은
  `src/api/` 규칙의 대상이 아니다.
- 빈 API 설정에서 제공하는 개발용 시뮬레이션은 프로덕션 데이터처럼 표현하지 않는다.

## 검증

```bash
rg -n '\b(fetch|axios)\b' src --glob '!src/api/**'
npm test

```
