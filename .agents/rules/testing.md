# Testing and Definition of Done

## 언제 읽는가

모든 코드 변경에서 읽는다.

## 테스트 선택

- 버그 수정: 실패를 재현한 회귀 테스트를 먼저 또는 함께 추가한다.
- 순수 계산·파싱·직렬화: 단위 테스트를 추가한다.
- API: 성공, HTTP 실패, 잘못된 응답, fallback을 검증한다.
- Store/Composable: loading, success, error, retry 상태 전이를 검증한다.
- 저장 구조 변경: 기존 데이터 마이그레이션과 손상 데이터 처리를 검증한다.
- 공용 UI: disabled, loading, keyboard, ARIA, `v-model` 동작을 검증한다.
- 날짜: 자정, 월말, 연말, 윤년, KST 경계를 검증한다.

소스 문자열 검사는 구조 규칙을 보호하는 보조 테스트다. 실제 렌더링, 이벤트,
상태 전이 테스트를 대체하지 않는다.

## 완료 조건

코드 변경은 다음 명령을 모두 통과해야 완료다.

```bash
npm test
npm run typecheck
npm run build
git diff --check
```

- 실패하거나 실행하지 못한 검증은 최종 보고에 명시한다.
- UI 변경은 [UI 컴포넌트 규칙](./ui-components.md)의 렌더링 검증까지 완료해야 한다.
  렌더링 도구를 사용할 수 없다면 자동 검증 결과와 별도로 미검증 사실을 보고한다.
- 외부 서비스가 필요한 테스트는 mock/fake로 결정적이게 만든다.
- 현재 날짜와 난수는 가능하면 주입해 테스트를 반복 가능하게 만든다.
- 테스트를 통과시키기 위해 검증 범위를 약화하지 않는다.

## 문서만 변경한 경우

문서 링크와 형식을 확인하고 최소 `git diff --check`를 실행한다. 문서 변경이 코드
동작이나 명령을 주장한다면 해당 명령도 실제로 확인한다.
